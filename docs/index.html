Write Gleam. Ship readable Clojure.

gleam-clj compiles Gleam, a small statically typed functional language, into idiomatic Clojure that runs on the JVM. The type checker guards your logic; the output reads like a person wrote it.

Get started → How it's verified
min_coins.gleam
/// Fewest coins summing to `amount`.
/// Error(Nil) if unreachable.
pub fn min_coins(coins: List(Int), amount: Int)
  -> Result(Int, Nil) {
  case amount {
    0 -> Ok(0)
    a if a < 0 -> Error(Nil)
    _ -> {
      int.range(1, amount + 1, ..)
      |> dict.get(amount)
    }
  }
}
compiles to
min_coins.clj
(defn min-coins
  "min_coins(coins: List(Int), amount: Int)
   -> Result(Int, Nil)

   Fewest coins summing to `amount`.
   Error(Nil) if unreachable."
  {:malli/schema [:=> [:cat [:sequential :int] :int]
                  (p/result-of :int :nil)]}
  [coins amount]
  (cond
    (= amount 0)   (p/->Ok 0)
    (< amount 0)   (p/->Error nil)
    :else (-> (int/range 1 (+' amount 1) ..)
              (dict/get amount))))

Getting started

From nothing to a running Clojure program

You need the Rust toolchain (to build the compiler), the Gleam CLI, and a JVM with the Clojure CLI. Then:

# build the compiler (links Gleam's real compiler front-end)
git clone https://github.com/escherize/gleam-clj
cd gleam-clj/gleam-to-clj && cargo build

# compile one Gleam file to a Clojure namespace
./target/debug/gleam-to-clj ../my_module.gleam my_module.clj

# or compile a whole project (src/, test/, and vendored hex deps)
./target/debug/gleam-to-clj build ./my-project ./out

The output namespace requires a small runtime (the prelude, an FFI core, and the compiled standard library) packaged as a git-dep so consuming code needs no Rust or Gleam toolchain. Run the result like any Clojure:

clojure -M -m my-module
;; => your program, on the JVM
The compiler fails loud. Anything it can't compile panics at build time with the feature named; nothing is silently dropped or mistranslated. That property is what makes the verification below meaningful.

Or skip the shuffle: call Gleam straight from Clojure

Once the compiler binary is built, one command compiles a Gleam snippet and calls it, no REPL setup:

# compile a Gleam fn and invoke it from Clojure in one shot
clojure -M:try 'pub fn add(a: Int, b: Int) -> Int { a + b }' add 2 40
;; => 42

# or drop into a REPL with the runtime + loader wired up
clojure -M:repl

From that REPL, gleam-clj.load compiles .gleam files on demand and loads the emitted namespace, cached by source hash, so re-loading unchanged source is free:

(require '[gleam-clj.load :as gl])

(gl/require-gleam "gleam-src/coin_change.gleam")   ;; => 'coin-change
(coin-change/min-coins (list 1 5 10) 13)           ;; => #Ok{:value 4}

(gl/eval-gleam "pub fn double(x: Int) -> Int { x * 2 }")
;; the snippet's public fns are now callable

And when the Gleam doesn't hold up, you get Gleam's own compiler error: the same diagnostic gleam build prints, right there in your REPL. Forget a variant in a case and the type checker names the one you missed before a single line runs:

(gl/eval-gleam "
  pub type Shape { Circle Square Triangle }
  pub fn name(s: Shape) -> String {
    case s {
      Circle -> \"circle\"
      Square -> \"square\"
    }
  }")

;; Gleam compile error:
;;
;; error: Inexhaustive patterns
;;   ┌─ …:4:5
;;   │
;; 4 │ ╭     case s {
;; 5 │ │       Circle -> "circle"
;; 6 │ │       Square -> "square"
;; 7 │ │     }
;;   │ ╰─────^
;;
;; This case expression does not have a pattern for all possible values.

That check runs in Gleam's real type checker (this project reuses it), so exhaustiveness, type mismatches, and syntax errors all surface with source spans and hints. Never a stack trace from the machinery underneath.

Compared to erlang & js

A third backend, held to the first two's standard

Gleam officially compiles to Erlang (the BEAM) and JavaScript. gleam-clj is an unofficial third target: the JVM, via Clojure. It reuses Gleam's own compiler front-end (the same parser and type checker), so a program that type-checks for the official backends type-checks here.

 → Erlang (BEAM)→ JavaScript→ Clojure (this)
Official?YesYesNo; community
IntegersArbitrary precisionf64 (unsafe past 2⁵³)Arbitrary precision via Clojure's +'. Matches BEAM, not JS.
ConcurrencyBEAM processes, OTPSingle-threaded, asyncJVM threads. OTP is out of scope.
Tail callsNative TCOTrampolinedSelf-calls → recur; mutual recursion is stack-bounded.
Interop targetErlang / ElixirJS / TS / browserClojure: plain records, keyword access, value equality.
Output you readGenerated ErlangGenerated JS/mjsIdiomatic Clojure, the point of the project.

The headline difference: the official backends generate code you're not meant to read. gleam-clj treats readable, idiomatic Clojure as the deliverable: kebab-case, docstrings, -> threading, records with keyword access. The output is code a Clojure team can review, call, and trust.

The runtime model

Three layers, and most of it is Gleam compiling itself

Compiled modules sit on a small runtime. Only the bottom sliver is hand-written; the bulk of the standard library is Gleam source, compiled by this same compiler.

gleam.prelude + stdlib

368 / 468 fns

The standard library's pure functions (folds, sorts, Result plumbing, string ops) are pure Gleam, so they're compiled, not reimplemented. They run Gleam's actual logic.

gleam-ffi: the native core

~110 fns

The only hand-written layer: Clojure implementations of every @external the stdlib bottoms out in: dict as a persistent map, graphemes via BreakIterator, UTF-8 byte ops, base64. The one place a bug could be silent, which is exactly where the fuzzers aim.

Data representation

zero-copy interop

Gleam values become the obvious Clojure ones: ints/floats/strings as-is, lists as seqs, tuples as vectors, custom types as defrecords. Keyword access, destructuring, and value equality work with no adapters.

Arithmetic compiles to Clojure's promoting operators (+', -', *') on purpose: Gleam ints are arbitrary precision on the BEAM, so unchecked longs would be wrong, not merely faster.

Custom types keep their sum-ness

A Gleam custom type is a closed set of variants. That structure survives the compile: each variant becomes a defrecord, they share a marker protocol so the sum type is a real Clojure thing (not a comment), and every variant plus the type itself gets a predicate.

shape.gleam
pub type Shape {
  Circle(Float)
  Rect(width: Float, height: Float)
  Point
}
compiles to
shape.clj
;; type Shape
(defprotocol IShape)
(defrecord Circle [^double value] IShape)
(defn Circle? [v] (instance? Circle v))
(defrecord Rect [^double width ^double height] IShape)
(defn Rect? [v] (instance? Rect v))
(defrecord Point [] IShape)
(defn Point? [v] (instance? Point v))
(defn Shape? [v] (instance? shape.IShape v))

Shape? is a plain instance? on the protocol's generated interface: an O(1) check, exactly as fast as the per-variant predicates, not a slow satisfies?. And every type gets a generated schema constructor: a Shape argument's schema is (Shape-schema), which validates the variant and its fields. Type parameters become schema-fn parameters, so nested types compose the way the Gleam type expression does. Note the ^double field hints: Float fields compile to primitive record slots, because the checker already proved they hold doubles.

Currencies that cannot mix, for free

Twenty lines: money tagged with a phantom currency type. The parameter exists only in the checker — the record at runtime is just {:cents n} — but adding dollars to euros is now a compile error, and the generated malli schemas keep the tag.

money.gleam
/// Money tagged with a phantom currency.
/// No runtime cost: the parameter exists
/// only in the type checker.
pub opaque type Money(currency) {
  Money(cents: Int)
}

pub type Usd

pub type Eur

pub fn usd(cents: Int) -> Money(Usd) {
  Money(cents)
}

pub fn eur(cents: Int) -> Money(Eur) {
  Money(cents)
}

/// Same-currency arithmetic only:
/// `add(usd(1), eur(1))` refuses to compile.
pub fn add(a: Money(c), b: Money(c))
  -> Money(c) {
  Money(a.cents + b.cents)
}

Note the phantom parameter surviving as [_currency] in Money-schema: type parameters become schema-fn parameters, and constructors that pin the currency (usd, eur) pin it in their schema too. This fixture runs in CI on both VMs.

coin_change.gleam
import gleam/dict.{type Dict}
import gleam/int
import gleam/list

/// Fewest coins summing to `amount`.
/// Error(Nil) if unreachable.
pub fn min_coins(coins: List(Int), amount: Int)
  -> Result(Int, Nil) {
  case amount {
    0 -> Ok(0)
    a if a < 0 -> Error(Nil)
    _ -> {
      int.range(1, amount + 1,
        dict.from_list([#(0, 0)]),
        fn(table, a) { step(coins, table, a) })
      |> dict.get(amount)
    }
  }
}

fn step(coins: List(Int),
        table: Dict(Int, Int),
        a: Int) -> Dict(Int, Int) {
  echo #("step", "a: ", a, ", table: ", table)
  let best =
    coins
    |> list.filter_map(fn(c) { dict.get(table, a - c) })
    |> list.reduce(int.min)
  case best {
    Ok(b) -> dict.insert(table, a, b + 1)
    Error(_) -> table
  }
}

pub fn main() {
  let assert Ok(0) = min_coins([1, 5, 10], 0)
  let assert Ok(1) = min_coins([1, 5, 10], 10)
  let assert Ok(2) = min_coins([1, 5, 10], 15)
  let assert Ok(4) = min_coins([1, 5, 10], 13)
  // greedy trap: greedy picks 4+1+1, optimal 3+3
  let assert Ok(2) = min_coins([1, 3, 4], 6)
  let assert Error(Nil) = min_coins([5, 10], 3)
  let assert Error(Nil) = min_coins([], 7)
}
compiles to
coin_change.clj · unedited
(ns coin-change
  (:require
   [gleam.dict :as dict]
   [gleam.int :as int]
   [gleam.list :as list]
   [gleam.prelude :as p])
  (:import (gleam.prelude Ok)))

(defn- step
  "step(coins: List(Int), table: Dict(Int, Int), a: Int) -> Dict(Int, Int)"
  {:gleam/src "coin_change.gleam:19"}
  [coins table a]
  (p/echo ["step" "a: " a ", table: " table] "coin_change.gleam:20")
  (let [best (-> coins
                 (list/filter-map (fn [c] (dict/get table (-' a c))))
                 (list/reduce int/min'))]
    (if (instance? Ok best)
      (let [b (:value best)]
        (dict/insert table a (+' b 1)))
      table)))

(defn min-coins
  "min_coins(coins: List(Int), amount: Int) -> Result(Int, Nil)

   Fewest coins summing to `amount`. Error(Nil) if unreachable."
  {:malli/schema [:=> [:cat [:sequential :int] :int] (p/result-of :int :nil)]
   :gleam/src "coin_change.gleam:6"}
  [coins amount]
  (cond
    (= amount 0)
    (p/->Ok 0)

    (< amount 0)
    (p/->Error nil)

    :else
    (-> (int/range 1
                   (+' amount 1)
                   (dict/from-list (list [0 0]))
                   (fn [table a] (step coins table a)))
        (dict/get amount))))

(defn main
  "main() -> Result(Int, Nil)"
  {:malli/schema [:=> [:cat] (p/result-of :int :nil)]
   :gleam/src "coin_change.gleam:31"}
  []
  (p/let-assert (p/->Ok 0) (min-coins (list 1 5 10) 0))
  (p/let-assert (p/->Ok 1) (min-coins (list 1 5 10) 10))
  (p/let-assert (p/->Ok 2) (min-coins (list 1 5 10) 15))
  (p/let-assert (p/->Ok 4) (min-coins (list 1 5 10) 13))
  (p/let-assert (p/->Ok 2) (min-coins (list 1 3 4) 6))
  (p/let-assert (p/->Error nil) (min-coins (list 5 10) 3))
  (p/let-assert (p/->Error nil) (min-coins (list) 7)))

(defn -main [& _]
  (main))

Each of these is the type checker's knowledge surviving into the output:

  • Docstrings lead with the checked Gleam signature: (doc min-coins) in a REPL tells you the real types, and the /// doc comment follows it.
  • :gleam/src names the origin. Every fn carries the .gleam file and line that defined it; even echo prints its source position.
  • Pipes become threading, guards become cond, with the pattern order the checker verified, not a heuristic rewrite.
  • Int math uses +'/-', Clojure's promoting ops, because Gleam ints are arbitrary-precision. Float args would get primitive ^double hints instead; see the runtime model.

Types that carry proof, and keep it through the compile

A bigger sample with opaque types: parse an untrusted user-id string once, mint a permission proof at the boundary, and let privileged functions demand the proof in their signature. The Gleam type checker makes unauthorized calls unrepresentable; the compiled Clojure keeps the discipline as instance? predicates and malli schemas:

permissions.gleam
pub opaque type UserId {
  UserId(Int)
}

/// Parse untrusted input into a UserId:
/// the only way to make one.
pub fn parse_user_id(raw: String)
  -> Result(UserId, IdError) {
  case string.trim(raw) {
    "" -> Error(Empty)
    trimmed ->
      case int.parse(trimmed) {
        Error(_) -> Error(NotANumber(trimmed))
        Ok(n) if n < 1 -> Error(OutOfRange(n))
        Ok(n) -> Ok(UserId(n))
      }
  }
}
compiles to
permissions.clj · excerpt, unedited
;; type UserId
(defprotocol IUserId)
(defrecord UserId [value] IUserId)
(defn UserId? "True if `v` is a UserId value."
  [v] (instance? UserId v))

(defn parse-user-id
  "parse_user_id(raw: String) -> Result(UserId, IdError)

   Parse untrusted input into a UserId:
   the only way to make one."
  {:malli/schema [:=> [:cat :string]
                      (p/result-of (UserId-schema) (IdError-schema))]
   :gleam/src "permissions.gleam:16"}
  [^java.lang.String raw]
  (let [subject (string/trim raw)]
    (if (= subject "")
      (p/->Error (->Empty))
      (let [trimmed subject subject (int/parse trimmed)]
        (cond
          (instance? gleam.prelude.Error subject)
          (p/->Error (->NotANumber trimmed))

          (and (instance? Ok subject) (< (:value subject) 1))
          (let [n (:value subject)]
            (p/->Error (->OutOfRange n)))

          (instance? Ok subject)
          (let [n (:value subject)]
            (p/->Ok (->UserId n))))))))

The ^java.lang.String hint comes from the checked argument type; the error variants each became a record you can dispatch on from Clojure. Note the return schema: (p/result-of …) carries the payload types, so an instrumented boundary rejects an Ok wrapping the wrong thing, not just a non-Result. Self tail calls become recur

The JVM has no tail-call elimination, so a naive translation of accumulator recursion would blow the stack. The compiler detects self tail calls and emits recur: constant stack, and the checked signature still leads the docstring.

sum_to.gleam
/// Sum 1..n with a tail-recursive
/// accumulator.
fn sum_to(n: Int, acc: Int) -> Int {
  case n {
    0 -> acc
    _ -> sum_to(n - 1, acc + n)
  }
}

pub fn main() {
  let assert 55 =
    sum_to(10, 0)
  let assert 500_000_500_000 =
    sum_to(1_000_000, 0)
}
compiles to
sum_to.clj · unedited
(ns sum-to
  (:require
   [gleam.prelude :as p]))

(defn- sum-to
  "sum_to(n: Int, acc: Int) -> Int

   Sum 1..n with a tail-recursive
   accumulator."
  {:gleam/src "sum_to.gleam:2"}
  [n acc]
  (if (= n 0) acc (recur (-' n 1) (+' acc n))))

(defn main
  "main() -> Int"
  {:malli/schema [:=> [:cat] :int]
   :gleam/src "sum_to.gleam:9"}
  []
  (p/let-assert 55 (sum-to 10 0))
  (p/let-assert 500000500000
    (sum-to 1000000 0)))

Only self tail calls get this treatment; mutual recursion stays JVM-stack-bounded, and the docs say so out loud in status & honest limits. The promoting +' means the millionth accumulation would promote past Long.MAX_VALUE instead of overflowing, exactly like the BEAM.

Verification & oracles

Every claim has an oracle

A compiler is only as trustworthy as its evidence. gleam-clj never asserts equivalence it didn't measure, and the measurement uses the official Gleam compiler as the source of truth.

Stdout-parity corpora

Every test program runs twice: once with the official Gleam compiler on the BEAM (the oracle), once compiled to Clojure on the JVM. Pass means byte-identical stdout; programs that crash on purpose must crash with matching output.

  • 54 / 54 runnable Rosetta Code tasks, byte-identical
  • 60 / 60 runnable Gleam language-tour lessons, byte-identical
  • A ratchet in CI: the passing count can never drop

Differential fuzzing

For the real-world port of Metabase's SQL-parameter parser, the upstream test table was ported and the two implementations were fed 5,000 random inputs across four modes: 20,000 comparisons against the original Clojure, zero divergence, down to which error type is thrown. It found a genuine runtime bug in minutes.

Fail loud, everywhere

Unsupported constructs panic at build time with the feature named. Labelled arguments are checked against real function signatures or refuse to compile. CI re-proves the whole chain on every push and narrates the method in its own logs.

The one soft spot: the FFI core is the only layer that can be silently wrong (everything else fails loud). That's precisely where every new real-world consumer, and every fuzzer, is aimed.
Benchmarks

Honest numbers, both VMs timing themselves

The benchmark project lives in bench/: the same Gleam runs on the BEAM via gleam run and on the JVM via this compiler, and each VM measures its own monotonic clock in-process, so startup is excluded. One warmup run, then three timed rounds; all rounds shown, no cherry-picking.

Read it plainly: dict-and-arithmetic code lands close to the BEAM, allocation-heavy list pipelines pay about 3×, and grapheme-level string slicing (glance's lexer) is where the JVM backend is weakest today. Writing this benchmark caught a real bug: string.join folded with <>, which BEAM's binary-append optimization makes linear and JVM string copying makes quadratic; it is now a StringBuilder-backed override, 9.5s → 9ms at 250k parts. That platform difference generalizes: a <> accumulation loop in your own code costs more here than on the BEAM.

Packaging

Consume it as an ordinary Clojure library

Compiled Gleam ships as plain Clojure source with a runtime snapshot: a git-dep, no exotic build step. Two libraries prove the model:

  • gleam-parser: glance, Gleam's own parser (written in Gleam), compiled to Clojure. It parses its own 2,300-line source on the JVM.
  • mb-lib-parse: Metabase's lib.parse rewritten in ~450 lines of Gleam and wired into Metabase itself; every consumer test passes on it.
;; deps.edn: pull a compiled-Gleam library like any git dep
{:deps {io.github.escherize/gleam-parser
        {:git/url "https://github.com/escherize/gleam-clj"
         :git/sha "..."
         :deps/root "libs/gleam-parser"}}}

Every public function carries {:malli/schema …} metadata derived from the Gleam types, so malli instrumentation and clj-kondo type-linting work out of the box, with zero runtime cost until you opt in. The rest of the checker's knowledge ships too: every fn's docstring leads with its Gleam signature, :gleam/src metadata names the defining .gleam file and line, and Float/String types become JVM type hints (^double, ^java.lang.String). That buys primitive math and reflection-free interop, with no annotations written by hand.

Status & honest limits

What it is, and what it isn't

gleam-clj is experimental but real: it compiles from Gleam's typed AST, self-hosts the standard library, runs actual hex packages, and drives a slice of Metabase. It is not a finished product, and these edges are deliberate:

No OTP
Erlang processes, supervisors, and the actor model don't map to the JVM and are out of scope. This is for pure and computational Gleam, not concurrent systems.
Mutual recursion is stack-bounded
Self tail-calls become recur; mutually recursive functions rely on the JVM stack and aren't trampolined.
FFI-backed hex packages need shims
Packages whose externals target Erlang/JS need a small Clojure implementation supplied via an externals map. Pure-Gleam packages just work.
Approximations, documented
Dict/set iteration is key-sorted to match BEAM small-map order; a handful of stdlib behaviors are noted in the repo. Graphemes are correct (BreakIterator).
