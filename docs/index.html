Write Gleam. Ship readable Clojure.

gleam-clj compiles Gleam — a small, statically typed functional language — into idiomatic Clojure that runs on the JVM. The type checker guards your logic; the output reads like a person wrote it.

min_coins.gleam
pub fn min_coins(coins, amount)
  -> Result(Int, Nil) {
  case amount {
    0 -> Ok(0)
    a if a < 0 -> Error(Nil)
    _ -> {
      int.range(1, amount + 1, ..)
      |> dict.get(amount)
    }
  }
}
compiles to
min_coins.clj
(defn min-coins
  {:malli/schema [:=> [:cat [:sequential :int] :int]
                  [:or [:fn p/Ok?] [:fn p/Error?]]]}
  [coins amount]
  (cond
    (= amount 0)   (p/->Ok 0)
    (< amount 0)   (p/->Error nil)
    :else (-> (int/range 1 (+' amount 1) ..)
              (dict/get amount))))

Getting started

From nothing to a running Clojure program

You need the Rust toolchain (to build the compiler), the Gleam CLI, and a JVM with the Clojure CLI. Then:

# build the compiler (links Gleam's real compiler front-end)
git clone https://github.com/escherize/gleam-clj
cd gleam-clj/gleam-to-clj && cargo build

# compile one Gleam file to a Clojure namespace
./target/debug/gleam-to-clj ../my_module.gleam my_module.clj

# or compile a whole project (src/, test/, and vendored hex deps)
./target/debug/gleam-to-clj build ./my-project ./out

The output namespace requires a small runtime — the prelude, an FFI core, and the compiled standard library — packaged as a git-dep so consuming code needs no Rust or Gleam toolchain. Run the result like any Clojure:

clojure -M -m my-module
;; => your program, on the JVM
The compiler fails loud. Anything it can't compile panics at build time with the feature named — nothing is silently dropped or mistranslated. That property is what makes the verification below meaningful.
Compared to erlang & js

A third backend, held to the first two's standard

Gleam officially compiles to Erlang (the BEAM) and JavaScript. gleam-clj is an unofficial third target: the JVM, via Clojure. It reuses Gleam's own compiler front-end — the same parser and type checker — so a program that type-checks for the official backends type-checks here.

The headline difference: the official backends generate code you're not meant to read. gleam-clj treats readable, idiomatic Clojure as the deliverable — kebab-case, docstrings, -> threading, records with keyword access — so the output is code a Clojure team can review, call, and trust.

The runtime model

Three layers, and most of it is Gleam compiling itself

Compiled modules sit on a small runtime. Only the bottom sliver is hand-written; the bulk of the standard library is Gleam source, compiled by this same compiler.

gleam.prelude + stdlib

368 / 468 fns

The standard library's pure functions — folds, sorts, Result plumbing, string ops — are pure Gleam, so they're compiled, not reimplemented. They run Gleam's actual logic.

gleam-ffi — the native core

~110 fns

The only hand-written layer: Clojure implementations of every @external the stdlib bottoms out in — dict as a persistent map, graphemes via BreakIterator, UTF-8 byte ops, base64. The one place a bug could be silent — which is exactly where the fuzzers aim.

Data representation

zero-copy interop

Gleam values become the obvious Clojure ones: ints/floats/strings as-is, lists as seqs, tuples as vectors, custom types as defrecords. Keyword access, destructuring, and value equality work with no adapters.

Arithmetic compiles to Clojure's promoting operators (+', -', *') on purpose: Gleam ints are arbitrary precision on the BEAM, so unchecked longs would be wrong, not merely faster.
Verification & oracles

Every claim has an oracle

A compiler is only as trustworthy as its evidence. gleam-clj never asserts equivalence it didn't measure — and the measurement uses the official Gleam compiler as the source of truth.

Stdout-parity corpora

Every test program runs twice: once with the official Gleam compiler on the BEAM (the oracle), once compiled to Clojure on the JVM. Pass means byte-identical stdout; programs that crash on purpose must crash with matching output.

  • 54 / 54 runnable Rosetta Code tasks — byte-identical
  • 60 / 60 runnable Gleam language-tour lessons — byte-identical
  • A ratchet in CI: the passing count can never drop

Differential fuzzing

For the real-world port of Metabase's SQL-parameter parser, the upstream test table was ported and the two implementations were fed 5,000 random inputs across four modes — 20,000 comparisons against the original Clojure, zero divergence, down to which error type is thrown. It found a genuine runtime bug in minutes.

Fail loud, everywhere

Unsupported constructs panic at build time with the feature named. Labelled arguments are checked against real function signatures or refuse to compile. CI re-proves the whole chain on every push and narrates the method in its own logs.

The one soft spot, named honestly: the FFI core is the only layer that can be silently wrong (everything else fails loud). That's precisely where every new real-world consumer — and every fuzzer — is aimed.
Packaging

Consume it as an ordinary Clojure library

Compiled Gleam ships as plain Clojure source with a runtime snapshot — a git-dep, no exotic build step. Two libraries prove the model:

  • gleam-parser — glance, Gleam's own parser (written in Gleam), compiled to Clojure. It parses its own 2,300-line source on the JVM.
  • mb-lib-parse — Metabase's lib.parse rewritten in ~450 lines of Gleam and wired into Metabase itself; every consumer test passes on it.
;; deps.edn — pull a compiled-Gleam library like any git dep
{:deps {io.github.escherize/gleam-parser
        {:git/url "https://github.com/escherize/gleam-clj"
         :git/sha "..."
         :deps/root "libs/gleam-parser"}}}

Every public function carries {:malli/schema …} metadata derived from the Gleam types — so malli instrumentation and clj-kondo type-linting work out of the box, with zero runtime cost until you opt in.

Status & honest limits

What it is, and what it isn't

gleam-clj is experimental but real: it compiles from Gleam's typed AST, self-hosts the standard library, runs actual hex packages, and drives a slice of Metabase. It is not a finished product, and these edges are deliberate:

No OTP
Erlang processes, supervisors, and the actor model don't map to the JVM and are out of scope. This is for pure and computational Gleam, not concurrent systems.
Mutual recursion is stack-bounded
Self tail-calls become recur; mutually recursive functions rely on the JVM stack and aren't trampolined.
FFI-backed hex packages need shims
Packages whose externals target Erlang/JS need a small Clojure implementation supplied via an externals map. Pure-Gleam packages just work.
Approximations, documented
Dict/set iteration is key-sorted to match BEAM small-map order; a handful of stdlib behaviors are noted in the repo. Graphemes are correct (BreakIterator).
